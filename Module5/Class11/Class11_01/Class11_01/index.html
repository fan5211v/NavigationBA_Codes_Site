    Class 11.1 - 数据的三种类型¶

    1. 数据类型概览¶

    我们本章来介绍数据获取：

    • 对于商业分析专业的同学们来说，数据获取的其实重要性不是那么高
    • 在学校的课程里，数据是老师给大家提供的，以后在企业中，数据会由专门的数据团队或 IT 团队提供，商业分析师的重点任务其实数据的分析

    • 在比较极端的情况下，商业分析师可能需要自己获取数据，例如：

      • 小规模的企业，可能分析是同时兼任 IT 人员和商业分析师的角色
      • 在外包场景下，目标公司是甲方，商业分析师是乙方，如果甲方自己都没有数据，那么乙方商业分析师就需要自己获取数据

    • 因此，关于数据获取的一些基本概念和方法，还是值得我们了解的

    在正式讲解数据获取的方法之前，我们需要先了解一下数据的三种类型：

    类型 举例 特点 工具 优势 挑战
    结构化 表格 预定义模式，行列组织 SQL、R 中的 dplyr、Python 中的 Pandas 易于存储、查询和分析 成本高，范围受限
    半结构化 JSON 有标记但不严格 R 中的 jsonlite 与 unnest 工具 灵活，保留层次关系 需要大量预处理才能分析
    非结构化 文字、图片、音频、视频 无固定模式 NLP、计算机视觉、AI 等工具 丰富、普遍 处理复杂，需要专门工具

    • 这种划分方式，简单理解就是从整齐到不整齐的一种划分方式：

      • 结构化数据是最整齐的，有行有列
      • 半结构化数据，类似于 JSON 文件，有一些标签和层次结构，但是没有表格那么整齐
      • 非结构化数据是最不整齐的，没有任何标签和层次结构，完全是杂乱的

    • 并且，从结构到非结构：

      • 一方面，数据是越来越不整齐，结构越来越复杂
      • 另一方面，数据是越来越灵活，包含的内容是越来越丰富的

    • 划分数据类型的目的在于：

      • 帮助理解不同类型数据的特点、优势和挑战，从而选择合适的工具和方法来处理它们
      • 对于商业分析师来说，理解这些数据类型有助于更有效地获取、清洗和分析数据，以支持业务决策

    2. 数据的三种类型¶

    (1) 结构化数据（Structured Data）¶

    结构化数据是遵循预定义模式（schema）的高度组织化数据：

    • 结构化数据简单理解，其实就是有行有列的表格，我们本学期接触过的 CSV 文件、Excel 文件、数据库、R 中的 tibble 数据框等都属于结构化数据
    • 预定模式指的是，数据结构在创建时就已经定义好了，数据必须遵循这个模式，这指的是表格的行和列严格规定了数据的结构，所有行都必须有相同的列

    • 结构化数据的例子包括：

      • 银行交易记录：日期、金额、发送方、接收方
      • 库存记录：产品、库存数量、单价
      • 员工人事记录：员工、薪资、部门

    • 这些例子的特点是，一行就可以把一个想要记录的实体（一笔交易、一件库存、一名员工）完整地描述出来，列则是这个实体的属性或特征

    结构化数据的典型构成：

    • 行（Record / Observation）：每行对应被描述实体的一个唯一实例（例如，一个客户、一笔销售交易）
    • 列（Field / Variable）：列代表实体的属性或特征（例如，客户年龄、交易金额）
    • 表（Table）：数据组织在可以通过共享变量或键相互关联的表中（例如，通过客户 ID 连接不同的客户数据表）

    结构化数据的优缺点：

    • 优势在于其精确性和可靠性
    • 局限性在于范围和规模有限，很多现实世界的数据和信息，例如我们上一章介绍的网购信息，无法轻易用整齐的行和列来捕获

    (2) 半结构化数据（Semi-Structured Data）¶

    半结构化数据虽然不像表格那样有严格的行列结构，但它仍然包含一些标记或标签来提供层次结构和组织：

    • 半结构化数据可以简单理解为我们上一章介绍的 JSON 文件，虽然它没有表格那么整齐，但它仍然有一些标签和层次结构来组织数据

    • 其实半结构化数据，可以看作是一种灵活的表格：

      • 行与行之间不需要遵循完全一致的列
      • 列与列之间不需要遵循完全一致的结构
      • 一个单元格中可以塞下多个值

    • 半结构化数据的例子包括：

      • 网购拍卖数据：一个拍卖中可以有多条竞价记录，每条竞价记录又包含竞价者的 ID、竞价金额、竞价时间等信息，这就需要嵌套的结构来表示
      • 社交媒体数据：一个社交媒体帖子可能包括多条评论，每条评论又包含评论者的 ID、评论内容、评论时间等信息，这也需要嵌套的结构来表示
      • 电子邮件：一个电子邮件可能包含多个收件人，每个收件人又包含姓名、电子邮件地址等信息，这也需要嵌套的结构来表示

    半结构化数据的优缺点：

    • 优势在于它的灵活性，能够捕获更复杂和多样化的信息，同时保留层次关系
    • 局限性在于它需要大量的预处理才能进行分析，尤其是当我们需要将半结构化数据转换为结构化数据时，可能需要进行复杂的数据清洗和转换，这个我们在上节课处理 JSON 文件时就已经体验过了

    (3) 非结构化数据（Unstructured Data）¶

    非结构化数据属于是完全没有预定义模式的数据：

    • 这些数据没有固定的模式，无法用行和列的表格来表示，也无法用任何嵌套的结构来表示

    • 非结构化数据的例子包括：

      • 文字数据：电子邮件、聊天消息、社交媒体帖子、产品评论、维基百科、新闻文章等
      • 多媒体数据：图像、音频、视频等

    • 事实上，非结构化数据是比结构化和半结构化数据更普遍存在的：

      • 这些数据对于人类来说，处理起来很高效
      • 但是计算机处理起来就非常困难了，因为它没有任何结构可言，计算机无法直接理解这些数据的内容和意义
      • 这个才是结构化数据真正的挑战所在

    非结构化数据的特点包括：

    • 缺乏标准化：

      • 非结构化数据类别繁多，即使在同一类别内，格式也可能各不相同
      • 设计计算机程序处理没有标准化格式和模式的数据会很困难

    • 规模和多样性：

      • 非结构化数据的规模巨大：每天数十亿条社交媒体帖子，还有无数图像、音频、视频等多媒体的上传
      • 格式的多样性需要针对每种类型的专门工具

    • 收集挑战：

      • 非结构化数据通常分散在各平台上，收集可能涉及：

        • 大量手工工作，比方说人工数据标注
        • 大型存储设施

      • 如果通过未授权的方式获取数据，例如网页抓取，还涉及法律法规上的限制

    • 处理要求：

      • 在分析之前，非结构化数据通常必须经过大量预处理和转换（例如，机器学习算法和 AI）：

        • 文本：分词、停用词去除、词干提取、情感标注
        • 图像：调整大小、标注、特征提取
        • 音频：降噪、语音转文字转录
        • 视频：帧提取、对象识别、动作识别

      • 也就是说，我们需要把数据整理成容易让计算机接受的样子
